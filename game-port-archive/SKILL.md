# 游戏移植收藏归档

让收藏者能从游戏目录打开中文说明，选对包，用自有游戏数据完成导入、构建或启动。

“先看看”只做筛查。“执行完整流程”把指定项目做到本地验收和所选云盘发布。用户另说“再查其他已有项目”时，先完成指定批次，再对剩余收藏及观察项执行同一流程。单项受阻时记录缺口，继续独立项目。

1. **查本地。** 从当前合集顶层项目记录、中央 manifest、观察清单、校验表和实际文件建立基线。清理链接里的中文标点，按 owner/repo 查重。同名游戏的不同移植分别建档；同一仓库的多游戏入口共享资源。沿用已有平台选择和源码保留决定，包括 Reignition 的 source_preserved=false。
2. **查上游。** 读作者的玩法记录、README、发行和构建说明。有目录页时交叉核实。已有实际玩法依据和明确构建路径即可收录源码构建版。只有菜单或开工记录的项目只记观察。区分新增、更新、无变化、观察、访问受阻，记录 UTC 时间和当地日期。比较完整提交以及附件 ID、更新时间、大小和摘要，识别同标签重传和发行平台迁移。[观察清单](references/watchlist.md)
3. **核对云端。** 同步范围是本地合集与一个选定的百度或 Google Drive 目录。每批首次写入及恢复续传前，核实本机服务进程、项目绑定账号和真实目标目录，定向读取相关目录及记录建立远端基线。百度使用当前授权的官方 uinfo.uk 与绑定值比较，Drive 核对授权账号、remote 和 root_folder_id。使用 MCP、CLI 或本机 API。连接失效时继续本地准备，按绑定恢复，排除 VPS、跨云和日常客户端登录态。[百度接入与恢复](references/baidu-openlist.md)
4. **备资源。** 每平台保留最新适用包，Windows 优先 x64，其次 x86，Android 默认 arm64。保留不可互替的功能和地区版本；Android 按新提交或明确更新范围处理。下载到 .part，核对大小和可用上游摘要后更名。源码锁定完整提交，递归保全固定子模块、LFS 实体和专用工具，通用 SDK 写入说明。失效依赖记录具体缺口，保留可用旧包。商业游戏数据由用户自备。
5. **验本地。** 在合集外暂存，核对 ZIP CRC、逐文件 SHA256、Git blob 和实际 PE/ELF 架构。以正式英文游戏名建目录，按需附作者或平台后缀。中文说明写清选包、入口、自备数据、构建或导入步骤、系统要求及存档。由项目记录生成同批索引。打包可用 scripts/archive_tools.py。[归档格式与特殊案例](references/archive-contract.md)
6. **发布并验收。** 先上传新资源并回读，再发布各项目说明和记录，随后更新中央清单、统计及目录入口。每步验证后再发布引用它的文件。逐文件记录旧值、目标摘要和进度，按下述验收规则续传。确认新版后清理明确被替代的包，历史只留来源与哈希。汇报项目数、版本、合集容量、上传及回读范围，并区分静态检查和游戏实测。[发布与验收](references/verification.md)
