# 游戏移植收藏归档

目标：让用户以后按“看中文说明 → 解压选定包 → 提供自有镜像/ROM或按向导导入”操作。做不到时明确标成研究源码、需本地生成、联网安装器或浏览器包，不把源码/安装器/更新包说成现成游戏。

## 收藏规则

- 沿用已有合集，先按GitHub `owner/repo` 去重、查当前记录；清除复制链接附带的中文标点并记下修正。关联依赖不另算主项目，同名游戏的不同移植不合并。
- 实时读取默认分支、完整提交、相关发行和作者说明；分别比较上次源码SHA、运行标签、附件名/哈希，报告“已收录或新增、源码变化、运行包变化”。无变化不重下；不能只凭仓库更新时间判断程序更新。发行列表按需翻页。
- Windows优先x64；只有32位现成包时按相同规格保留x86。核对EXE及DLL的PE头，不信文件名。必需32位辅助工具不等于另一个32位游戏版本。
- 一般只留一个最新适用版本，便携ZIP优先。不要因Alpha标记自动跳过更新；稳定/实验选择看功能、地区、限制和作者建议。只有不能覆盖的地区、功能、后端或稳定路径才保留额外包，说明默认选择及原因。Android新版本号不等于Windows更新。
- 最终只留压缩归档，清除已保全的展开目录。源码要纳入已经补下的专用子模块，不能仅留最初不含子模块的source.zip。中文说明、更新快捷方式、当前文件记录放在外面，旧路径记录归入历史。
- 通用Python、Git、VS、CMake、Rust、驱动等只说明要求，不额外下载。上游运行包自带的DLL、资源、工具、运行时及许可证完整保留。项目专用框架、固定编译器、特殊补丁/配置、配套引擎等另行保全；共享专用工具集中压缩。

## 执行流程

1. **比对现有记录。** 读取当前manifest和主项目顶层记录；不要递归把历史记录当项目。快照旧记录，写检查时间（UTC及用户本地日期）。无网络时不声称确认了最新。
2. **追溯官方发行。** 读README、发行/构建/游戏文件文档、资源清单、`.gitmodules`、`.gitattributes`和必要脚本。发行迁移时跟随作者的新平台链接，不能把GitHub旧包充当全网最新。连接受阻时记录证据、保留官方地址，继续独立可做部分。
3. **暂存下载。** 源码锁定完整SHA；附件保留原URL、大小、本地SHA256和实际核对过的作者校验/GitHub digest。下载用.part，成功才原子更名。同名附件哈希改变时不能复用旧缓存。不要为归档执行下载的游戏/安装器。
4. **补齐再压缩。** 普通源码ZIP没有git子模块，按父提交gitlink SHA递归补专用模块，记录仓库、路径、SHA及归档哈希。失效提交不换成最新。通用开发库可仅记录；识别LFS指针，补真实文件或明确缺口。原文文档、离线Wiki和依赖许可证保全。
5. **准备最少操作路径。** 缺Game.dll/配套引擎则配好同架构同分支；错标RAR等转真正ZIP。保留所有必需文件和来源，可附中文使用说明。优先上游启动/本地服务器脚本。浏览器包、需镜像生成的安装器、联网依赖要明确；没有用户游戏数据时不能凭空生成最终游戏。
6. **验证后再清理。** 用 `scripts/archive_tools.py pack` 或等价方法逐文件SHA256、打包后读回比对及CRC检查。原source.zip与合并归档另核对覆盖；有差异保全原包。新包验证完才替换旧包、移除展开目录/其他平台/可替代旧版。确认删除绝对路径在目标合集内，且没有混入用户存档/数据。不把文件搬到别处冒充节省空间。
7. **同步交付。** 更新中文说明、HTML索引、CSV、manifest、当前SHA清单、版本取舍和审计/体积统计。先生成报告再检查链接；主项目数一致，当前清单只引用真实文件，无.part或展开目录。旧URL、哈希、缺口留在历史区。增量只验新增/改变归档，除非出现新完整性疑点。

结构、中文说明要求、实际案例和报告边界见 [references/archive-contract.md](references/archive-contract.md)。需要打包或识别架构时：

```text
python scripts/archive_tools.py inspect FILE [--crc]
python scripts/archive_tools.py pack SOURCE_DIR OUTPUT.zip --prefix source
```

脚本不覆盖旧文件、不删除输入，生成内部逐文件清单和外部验证记录，先在暂存区运行。归档不修改应用源码或上游版本，不人为给游戏加版本号；另行开发应用功能时遵守其版本规范。

交付简报用中文：已有无变化/新增/更新、保留版本及架构、额外操作和未验证边界、合集实际路径/大小。
