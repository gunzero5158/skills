# 收集模式：建立宣传档案

触发条件：调用 skill 时没有可用档案，或用户明确要新建/更换产品档案。
终点：一份经用户确认的 `profiles/<名称>.md`，结构对齐 `profiles/_template.md`（拿它当模板，`example-bridgeapi.md` 是填好的架空示范）。

## 路径 A：用户有现成资料

用户丢来 pitch deck、官网链接、已发过的信件、产品文档等。做法：

1. 通读全部资料（PDF 用 Read，官网用 WebFetch）。
2. 按档案模板逐节抽取：主体信息／业务介绍与卖点／价格口径／合作方案／红线／格式规范。
3. **抽不到的不要编**。空缺项列出来问用户，尤其是红线（资料里通常不写「什么不能说」，但这恰恰最重要）和发信人署名。
4. 已发过的信件是最有价值的输入：从中反推格式规范和语感，并直接收进 `-examples.md`。
5. 草稿给用户过目，逐节确认后落盘。

## 路径 B：访谈建档

没有现成资料时，分轮提问，每轮 2~3 个问题，不要一次性甩一张长表。

**第一轮（业务）**
- 用一两句话说说产品是什么、卖给谁？有产品/公司官网吗？（有 URL 就去抓，能省后面很多问题）
- 希望被触达的人做什么动作？（成为客户／帮忙引荐介绍／只是混个脸熟）

**第二轮（方案与数字）**
- 给对方的具体好处是什么？（折扣？分成？免费试用？给出可写进信里的数字口径）
- 价格/优惠允许写到多具体？有没有「只能说到这、再多留到报价阶段」的界线？

**第三轮（红线与格式）**
- 有什么绝对不能写的？（法律/资质坑、竞品词、夸大表述、公司规定）
- 署名怎么落：发信人姓名（外语名注意确认正确写法和分隔符）、职务、邮箱、网址？
- 语言与文体偏好？（敬语程度、可否邀约会议/电话、CTA 风格）

**第四轮（策略）**
- 未回复要不要追发？追几次、间隔多久？
- 遇到「営業お断り」的对象怎么处理？

访谈中用户的每个回答都可能带出新问题（比如提到「我们还没取得某资质」→追问哪些相关词要进禁词表）。问完把草稿整理给用户确认，再落盘。

## 落盘检查

- 文件名用产品名小写 kebab-case：`profiles/<name>.md`
- 红线禁词表和格式规范两节必须存在，哪怕暂时只有一两条
- 首行写「最后更新：日期」和口径来源说明
- 有范例信件的建 `profiles/<name>-examples.md`
