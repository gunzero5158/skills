# 待观察项目

用户希望保留尚不可玩的项目线索时，以轻量记录纳入整个合集，不下载大资源。

- 当前机器清单位于 `_归档记录/当前管理记录/待观察项目.json`，中文列表可放根目录并链接到总HTML目录及项目总表。与有文件的项目分开计数，现有归档manifest只列实际归档项目，避免验收器误要求不存在的文件。
- 至少记录正式英文名称、规范repository或尚未识别的原页面URL、status、暂缓原因、证据来源、检查日期、观察到的提交/发行（如可取得）。空仓库地址必须明确待识别，不能以搜索到的同名项目冒充原页面目标。
- 状态区分 `watch_unplayable`（尚未可玩）、`watch_unavailable`（404/私有/无法核实）、`watch_non_pc`（仅非PC/Android目标）、`watch_unresolved`（页面受阻且仓库未确认）。访问失败不能写成不可玩；不把旧历史判断说成本次实时结论。
- 恢复历史删除记录只恢复地址、原因和来源，不恢复被删除大包。非PC项目只留线索，只有以后明确新增可玩PC或Android目标（不追溯补齐旧安卓资源）才进入下载候选。
- 每次用户要求同步合集时，同时检查观察名单；提交变化只触发重新阅读可玩性证据，不自动触发下载。符合下载条件后，以仓库身份迁入实际归档manifest，在观察记录中保留晋级时间与目标目录或移入历史，避免重复项目和重复资源。
- 待观察清单、中文页面和索引一并同步Drive；不为此擅自建立定时任务。
