# 本地与百度网盘同步

## 范围与连接

- 本流程只处理本地归档与用户选定的百度目录之间的上传、下载和核对。按任务明确源位置、目的地和传输方向；不调用其他云盘作为源或中转。
- 读取本机 LOCALAPPDATA/GamePortArchive/baidu_connection.json 等既有连接记录，核实账户、目标目录及本机实际运行的客户端或服务。记录是定位线索，缺失时检查本机安装和配置，不猜测入口。
- 使用OpenList时核对实际服务进程；loopback地址可能是远端隧道，不能据此认定是本机服务。本机连接不可用时恢复本机连接，保留已准备资源及同步进度，不切换到远端服务。
- 挂载路径是界面入口；按驱动、存储ID及真实root_folder_path核对百度目标，不依赖可修改的挂载名称。用户其他资料目录不属于归档操作范围。
- 百度流量是否经过VPN取决于实际路由和分流；连接成功或禁用应用代理都不能证明流量直连。不得未经用户要求修改系统路由、VPN或防火墙。

## 自动化与多账号绑定

- 本合集批量列目录、上传和内容校验使用网盘 MCP、CLI 或本机 OpenList API；不使用 computer-use 操作日常百度客户端。客户端当前登录账号不是本项目账号的证据。
- 私有连接记录至少保存本地合集绝对路径、服务地址、真实服务进程/数据目录、storage_id、driver、mount_path、root_folder_path、百度稳定账号标识（官方 uinfo 的 uk）和核实日期；凭据与账号名不写入合集或公共仓库。对外可用 uk 的 SHA256 短前缀区分绑定。
- 每次恢复连接后从百度官方接口再次取得账号标识，并检查原目录的当前 manifest 与相关项目记录；身份、目录或记录不一致时停止写入并解决差异，不能仅凭挂载显示名相同就判为原账号。

## 本机 OpenList 丢失后的重建

1. 在实际本机权限下检查私有连接记录、既有启动脚本、安装路径、进程及监听端口。沙箱不可读不等于文件丢失；localhost 可能是 SSH 隧道。只做有线索的定向查找。
2. 从 OpenList 官方发行获取适用本机 CLI，核验官方 digest；创建独立私有数据目录，仅监听回环地址的独立端口。不要照搬远端 Linux 路径、整个数据库或 Google 桥接配置。
3. 按当前官方版本完成管理员初始化。v4.2.9 首次无管理员时，先读 `/api/public/init_status`，再调用 `/api/public/init/setup`；仅有管理 token 不证明已初始化，可能返回 `record not found`。密码/令牌在私有目录保管，不输出进程参数或日志。
4. 若用户允许恢复且本机留有原项目挂载快照，可只读取匹配原百度根目录的授权及驱动字段，迁入新建的本机实例；快照曾用于远端部署不等于允许连接该远端。不得导入其他账号/挂载、Google源、远端服务地址、远端执行或隧道。没有可核实的原授权时由用户完成指定账号的官方授权，不从日常客户端提取会话替代。
5. 通过本机 `/api/admin/storage/create` 或 `update` 恢复单一百度挂载，并按当前驱动类型检查参数。v4.2.9 `upload_thread` 是字符串。驱动错误可能夹带凭据，日志只输出状态码、阶段及脱敏摘要，不直接打印 addition、raw_url 或错误全文。
6. 官方 `/rest/2.0/xpan/nas?method=uinfo` 确认账号，定向读取原 manifest/项目记录做漂移检查，再上传一个本轮确实需要的小文件并完整回读核验。之后才上传大包；大包回读独立验收，不能由小文件测试代替。
7. 固化本机连接记录和仅启动该本机服务的入口。新包上传记录与回读记录分开，失败后先复核已上传文件，避免重复上传。管理员 Authorization 只发给本机 OpenList，不能随百度直链请求发送。

这些步骤仅恢复“本地 ↔ 指定百度账号”接入，不建立或运行跨云链路。

## 授权与诊断

- 用户在官方登录页完成授权；令牌仅放本机私有配置，不写入聊天、合集或公共Git仓库。
- 使用OpenList时区分Refresh Token和Access Token，按实际客户端模式配置；错误信息与日志须避免回显凭据。
- 授权、可列目录、可上传、可下载和校验通过是不同状态。连接建立或修复后，用小文件真实上传并回读验证；大包兼容性需要验证时使用本轮待上传包，避免重复测试传输。

## 同步与验收

- 本地盘点和上游增量判断在先，云端定向复核在后；实际写入前复查目标记录和文件，发现漂移先处理差异。相同内容跳过，未确认的同名不同内容不得覆盖。
- 发布前分别统计待上传量、待下载/回读量与预计净增容量。更新ZIP通常需要整包传输，净增容量不能作为流量估计。
- 已确认的版本更新先上传至独立暂存路径或新版本文件名并校验，再发布一致的新记录；随后删除明确被替代文件及本轮暂存内容，不建立旧包备份区。失败时保留旧版及续作证据，不以不完整暂存目录运行删除型sync。
- 无服务端SHA256时以实际下载回读计算摘要；不得把本地摘要当作云端证明。HTTP Range校验须检查206、Content-Range和分段长度，并按顺序计算完整SHA256。
- 校验在本机执行，限制并发及在途缓冲；不要一次保留数GB分片。检查本机服务的实际暂存目录和磁盘余量，仅清理已确认用途且无活动任务占用的缓存。
- 首次全量同步及最终验收按明确范围刷新、分页读取云端目录，核对路径、数量、大小、重复项及可用哈希。未管理文件单列保留，不据差集删除。上传完成不等于回读或目录验收完成。
- 回读完成后才更新本地当前记录和清理替代旧包；保留用户游戏数据、存档及其他额外文件。报告实际链路、传输量及未验证边界。
